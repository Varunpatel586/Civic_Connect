# Render Deployment

The repository includes a `render.yaml` Blueprint for the Node.js API. It
deploys the `server` directory as a Render web service with `npm ci`, `npm
start`, and `/health` as the health check.

## Before deploying

1. Create a MongoDB Atlas database and allow the Render outbound connection.
2. Push the repository to GitHub or GitLab.
3. In Render, choose **New > Blueprint**, select the repository, and apply the
   Blueprint.
4. Set `MONGO_URI` to the Atlas connection string.
5. Set `API_URL` to the API's public Render URL, without `/api`, for example
   `https://civic-connect-api.onrender.com`.
6. Set `CORS_ORIGINS` to the public origins that need browser access. Native
   Flutter clients do not require CORS.
7. Add `GOOGLE_CLIENT_IDS` if Google sign-in is enabled. Use a comma-separated
   list when more than one client ID is valid.

`JWT_SECRET` is generated by the Blueprint. Keep it stable after deployment;
changing it signs out every existing session.

## Flutter production configuration

Set the bundled client environment value to the deployed API:

```ini
API_BASE_URL=https://civic-connect-api.onrender.com/api
```

Build the Flutter app after changing this value. Do not put server-only secrets
such as `MONGO_URI` or `JWT_SECRET` in the Flutter environment file.

## Uploads and redeploys

The API stores photographs in `server/uploads`. The Blueprint attaches a 1 GB
Render persistent disk at that directory. Without a persistent disk, uploaded
photographs can disappear when the service is redeployed or restarted while
MongoDB still contains their URLs. Increase the disk or move uploads to object
storage before production growth.

## AI clustering

The Node API can run without the AI service; issue creation skips visual
duplicate detection when `AI_SERVICE_URL` is unset. Failed AI calls also fall
back to normal issue creation. `npm start` does not launch Python. Therefore
the first Render deployment can leave `AI_SERVICE_URL` unset.

The current AI contract passes local filesystem paths, so deploying
`ai_service` as a separate Render service will not work by setting a URL alone.
Both services would need a shared object-storage image contract, or the Node
API would need to send image data to the AI service. The local `npm run dev`
workflow remains unchanged.

## Smoke test

After deployment, open:

```text
https://civic-connect-api.onrender.com/health
```

The response must be HTTP 200 with `{"status":"ok","database":"connected"}`.
