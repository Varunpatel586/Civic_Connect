# Render Deployment

The repository includes a `render.yaml` Blueprint for two Render web services:
the Node.js API and the Python FastAPI vision service. They are deployed
independently, but the Node API calls the AI service over its public HTTPS URL.

## Before deploying

1. Create a MongoDB Atlas database and allow the Render outbound connection.
2. Push the repository to GitHub or GitLab.
3. In Render, choose **New > Blueprint**, select the repository, and apply the
   Blueprint.
4. Set `MONGO_URI` to the Atlas connection string on `civic-connect-api`.
5. Set `API_URL` on `civic-connect-api` to the API's public Render URL, without `/api`, for example
   `https://civic-connect-api.onrender.com`.
6. Set `AI_SERVICE_URL` on `civic-connect-api` to the AI service's public URL,
   for example `https://civic-connect-ai.onrender.com`.
7. Set `CORS_ORIGINS` to the public origins that need browser access. Native
   Flutter clients do not require CORS.
8. Add `GOOGLE_CLIENT_IDS` if Google sign-in is enabled. Use a comma-separated
   list when more than one client ID is valid.

`JWT_SECRET` is generated by the Blueprint. Keep it stable after deployment;
changing it signs out every existing session.

## Flutter production configuration

Set the bundled client environment value to the deployed API:

```ini
API_BASE_URL=https://civic-connect-api.onrender.com/api
```

Build the Flutter app after changing this value. Do not put server-only secrets
such as `MONGO_URI` or `JWT_SECRET` in the Flutter environment file.

## Uploads and redeploys

Photographs are stored in MongoDB (GridFS) and re-encoded with `sharp` to a
bounded JPEG on the way in, so no persistent disk is attached to the API
service. Uploaded files survive redeploys and restarts for free, and the
compression keeps the storage inside Atlas M0's 512 MB database ceiling: a
5 MB phone photograph lands at a few hundred kilobytes. Files that predate the
migration, and the seed images, are still served from the legacy
`server/uploads/` directory by the same `/uploads/:filename` route.

Keep an eye on MongoDB storage as the complaint count grows — the binary bytes
share the database's cap with the application documents, and real production
growth still wants object storage.

## AI clustering

The AI service is configured by the second service in `render.yaml`:

| Setting | Value |
|---|---|
| Plan | `standard` or another plan with at least 2 GB RAM |
| Root directory | `ai_service` |
| Build command | `pip install -r requirements.txt` |
| Start command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
| Health check | `/health` |

Do not use `npm run dev` or `uvicorn --reload` in Render. Those are local
development commands. The AI service loads CLIP during startup, so the first
deployment can take several minutes and needs enough memory for PyTorch and the
model. The free 512 MiB instance is not sufficient; use a plan with at least
2 GB RAM. Watch the AI service logs until its health check becomes healthy.

The two services have separate filesystems. The API keeps photographs on its
Render persistent disk and exposes them through `/uploads`. For comparison,
the API sends HTTPS image URLs to FastAPI; FastAPI downloads them into a
temporary directory and removes them after the request. This is why the API's
`API_URL` must be correct and publicly reachable by the AI service.

Classification and severity endpoints do not require a shared filesystem; they
receive image uploads directly in the request.

If `AI_SERVICE_URL` is unset, issue creation still succeeds but visual duplicate
detection is skipped. If the AI service is unavailable, the API logs the error
and creates a standalone issue instead.

## AI service deployment steps

1. Push the repository with the updated `render.yaml`.
2. In Render, choose **New > Blueprint**, select the repository, and apply it.
3. Confirm that Render creates both `civic-connect-api` and `civic-connect-ai`.
4. Wait for `civic-connect-ai` to finish installing Python, OpenCV, Torch,
   Transformers, and the CLIP model.
5. Open `https://civic-connect-ai.onrender.com/health`. A healthy response has
   HTTP 200 and a JSON body containing `"status":"ok"`.
6. Copy that AI service URL into the API service's `AI_SERVICE_URL` environment
   variable and redeploy the API.
7. Open the API health endpoint and verify MongoDB is connected.
8. Test classification through the API's authenticated issue classification
   route, then test a second nearby issue with a similar image to exercise
   duplicate matching.

The Render free plan may suspend either service. The first request after sleep
can be slow, and the AI service may need to reload the CLIP model. The AI
service specifically cannot run reliably on the free 512 MiB plan because the
model and its Python runtime exceed the memory limit.

## Smoke test

After deployment, open:

```text
https://civic-connect-api.onrender.com/health
```

The response must be HTTP 200 with `{"status":"ok","database":"connected"}`.
